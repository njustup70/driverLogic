## 3. 已确定的架构方向

1. **通信层将来可能改为 eRPC**（<https://github.com/EmbeddedRPC/erpc>），但**不会立刻改**。
   - 因此现在就要把"业务动作"与"字节帧"隔离开：上层不知道 `0xFA/0xFF/opcode/CRC`。
   - eRPC 自带 6 字节帧头（crcHeader/messageLength/crcBody，CRC16）、函数 ID、超时与通知机制，Python 端有 `SerialTransport`；迁移时只替换 transport 与生成的 stub，不动决策层。
2. **控制层（底盘/机构/夹爪/矛）与决策层（比赛流程/状态机）分成两个目录**，只通过动作 API + 共享状态交互。
3. **单动作（single action）是基本单元**：夹爪开合、机构升降、取矛、对矛、转向、到点等，每个都能独立下发并等待 ACK。
4. 组内算法模块（视觉、定位、路径规划）以**适配器（adapter）**形式接入，不直接改主逻辑内部。

## 5. 术语

| 术语 | 含义 |
|---|---|
| R1 / R2 / R2n | R1、R2 是两套车；`R2n` 是 R2 的变体入口，当前默认（速度测试） |
| 梅林 / Merlin | 场地上的格位/桩位机构 |
| 二区 / zone2 | 取块与放置区域；历史上有一套 `zone2_model` 路径求解 |
| 单动作 | 可独立下发、独立完成、独立 ACK 的最小机构动作 |
| ACK | 下位机执行完单动作后的完成回包（历史为 `0x6F`） |
| 外参 | `sick2Base`、`map2BaseInit`、`base2laser`、`base2odin` 等安装参数 |
| 融合位姿 | `map -> base_link`，由 odom + SLAM + SICK 修正得到 |

## 6. 工作约定（重构期间）

1. **协议单一真源**：opcode、帧格式、状态码只允许在一个模块（未来 `protocol/`）定义；禁止在业务代码里写 `b'\xA1'`。
2. **文档先行**：改协议先改 `docs/20-single-action-protocol.md`，再改代码，再通知电控。
3. **不提交垃圾**：`.DS_Store`、`__pycache__`、`*.pyc`、本地标定 `*.npy` 不入库。
4. **不静默吞异常**：禁止裸 `except:`；串口/协议错误至少 `logging.warning` 并计数。
5. **每个入口必须可导入**：`python -c "import MainLogic.MAIN.xxx"` 是最低门槛；CI 后续补上。
6. **命名**：新代码用 `snake_case` 函数、`PascalCase` 类；不要再出现 `chassic`、`decorder` 这类拼写。
